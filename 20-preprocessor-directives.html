20.1 Introduction to the C Preprocessor

Before a C program is compiled, its source code goes through a preprocessing stage. The C preprocessor handles special instructions called preprocessing directives.

These directives can include header files, define macros, remove macro definitions and conditionally include portions of source code.

Simple Definition:

The C preprocessor is a program or processing stage that performs source-code transformations before the compiler compiles the resulting source.

20.2 What is a Preprocessor?

The preprocessor is the part of the C translation process that processes preprocessing directives before the compiler analyzes the resulting source code.

It does not normally execute the C program. Instead, it prepares the source code for compilation.

Examples of Preprocessor Directives

#include <stdio.h>

#define PI 3.14159

#ifdef DEBUG

#endif

20.3 Preprocessing Stage

A simplified view of the C program translation process is:

C Source Program | v Preprocessing | v Translated Source | v Compilation | v Object Code | v Linking | v Executable Program

The exact implementation details can vary between compilers, but preprocessing conceptually occurs before compilation of the resulting source.

20.4 Preprocessor Directives

Preprocessor directives begin with the # character.

Examples

#include <stdio.h>

#define MAX 100

#undef MAX

#ifdef DEBUG

#endif
A preprocessor directive is not an ordinary C statement. It is handled during preprocessing.

20.5 Types of Preprocessor Directives

Directive Purpose
#include Includes a header file or source file.
#define Defines a macro.
#undef Removes a macro definition.
#if Conditionally includes code based on an expression.
#ifdef Checks whether a macro is defined.
#ifndef Checks whether a macro is not defined.
#else Selects the alternative conditional branch.
#elif Provides another conditional branch.
#endif Ends a conditional preprocessing block.

20.6 #include Directive

The #include directive is used to make the contents of a header file available to the source file.

Syntax

#include <header-file>

Example

#include <stdio.h>

This is commonly used when a program needs declarations for standard input/output functions such as printf() and scanf().

20.7 System Header Files

Header files provided by the implementation are commonly included using angle brackets. 

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <math.h>
Header Common Purpose
stdio.h Input and output facilities.
stdlib.h General utility functions.
string.h String and memory functions.
math.h Mathematical functions.

20.8 User-Defined Header Files

A programmer can create a header file and include it using double quotation marks. 

#include "myheader.h"

This style is commonly used for project-specific header files.

20.9 #define Directive

The #define directive defines a macro.

Syntax

#define NAME replacement

Example

#define PI 3.14159

After preprocessing, occurrences of the macro name can be replaced according to the macro definition.

20.10 Object-Like Macro

A macro without parameters is called an object-like macro. 

#define MAX_SIZE 100

Example Program

#include <stdio.h>

#define MAX_SIZE 100

int main()
{
    printf("Maximum size = %d", MAX_SIZE);

    return 0;
}

Output

Maximum size = 100

20.11 Symbolic Constants

Macros are sometimes used to give meaningful names to constant values. 

#define DAYS_IN_WEEK 7
#define MONTHS_IN_YEAR 12
#define PI 3.14159
Meaningful names can make source code easier to understand. However, for typed constants in modern C, const objects or enum values may often be preferable depending on the use case.

20.12 #define with Strings

A macro can also represent a string literal. 

#define COLLEGE "ALLIED"

#include <stdio.h>

int main()
{
    printf("College: %s", COLLEGE);

    return 0;
}

Output

College: ALLIED

20.13 #define and Expressions

#define WIDTH 10
#define HEIGHT 20

#include <stdio.h>

int main()
{
    int area = WIDTH * HEIGHT;

    printf("Area = %d", area);

    return 0;
}

Output

Area = 200

20.14 Important Point About Macros

A macro is not a variable. It represents a preprocessing replacement mechanism. 

#define VALUE 10

The preprocessor can replace occurrences of VALUE according to the macro definition before compilation.

20.15 Function-Like Macros

A function-like macro contains parameters inside parentheses.

Syntax

#define NAME(parameter) replacement

Example

#define SQUARE(x) ((x) * (x))

The macro can be used as: 

int result = SQUARE(5);

Result

25

20.16 Program Using Function-Like Macro

#include <stdio.h>

#define SQUARE(x) ((x) * (x))

int main()
{
    int n = 6;

    printf("Square = %d", SQUARE(n));

    return 0;
}

Output

Square = 36

20.17 Why Parentheses Are Important in Macros

Macro parameters and the complete replacement expression should usually be parenthesized when arithmetic expressions are involved.

Unsafe Style

#define SQUARE(x) x * x

Safer Style

#define SQUARE(x) ((x) * (x))

Parentheses help prevent unexpected results caused by operator precedence.

20.18 Macro Side Effects

Function-like macros can evaluate their arguments more than once. 

#define SQUARE(x) ((x) * (x))

Using: 

SQUARE(i++)

can produce unexpected behavior because the argument may be expanded more than once.

Be careful when passing expressions with side effects to function-like macros.

20.19 Macro for Maximum

#include <stdio.h>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main()
{
    int x = 10;
    int y = 20;

    printf("Maximum = %d", MAX(x, y));

    return 0;
}

Output

Maximum = 20

20.20 #undef Directive

The #undef directive removes a macro definition.

Example

#define VALUE 100

#undef VALUE

After #undef VALUE, the macro VALUE is no longer defined.

20.21 Program Using #undef

#include <stdio.h>

#define VALUE 10

int main()
{
    printf("%d\n", VALUE);

#undef VALUE

    return 0;
}

Output

10

The #undef directive is processed before compilation and removes the macro for subsequent preprocessing.

20.22 Conditional Compilation

Conditional compilation allows selected portions of source code to be included or excluded during preprocessing.

Common directives include: 

#if
#ifdef
#ifndef
#else
#elif
#endif

20.23 #if Directive

The #if directive includes a section of code when its preprocessing condition evaluates to a nonzero value.

Example

#define VERSION 2

#if VERSION == 2

printf("Version 2");

#endif

20.24 #ifdef Directive

#ifdef checks whether a specified macro has been defined. 

#define DEBUG

#ifdef DEBUG

printf("Debug mode");

#endif

If DEBUG is defined, the selected code is included.

20.25 #ifndef Directive

#ifndef means "if not defined". 

#ifndef VALUE

#define VALUE 100

#endif

The macro is defined only if VALUE has not already been defined.

20.26 Header Guards

Header guards are commonly used to prevent a header file from being processed multiple times in the same translation unit. 

#ifndef MYHEADER_H
#define MYHEADER_H

/* Header declarations */

#endif
Header guards are one of the most important practical uses of #ifndef, #define and #endif.

20.27 Header Guard Flow

Include Header | v Is MYHEADER_H defined? / \ Yes No | | v v Skip Define header MYHEADER_H | v Process header | v END

20.28 #else Directive

The #else directive provides an alternative section when the preceding conditional condition is false. 

#ifdef DEBUG

printf("Debug mode");

#else

printf("Normal mode");

#endif

20.29 #elif Directive

The #elif directive allows additional conditional branches. 

#if VERSION == 1

printf("Version 1");

#elif VERSION == 2

printf("Version 2");

#else

printf("Other version");

#endif

20.30 #endif Directive

The #endif directive marks the end of a conditional preprocessing section. 

#ifdef DEBUG

printf("Debug");

#endif
Every conditional preprocessing block must be properly terminated.

20.31 Conditional Compilation Example

#include <stdio.h>

#define DEBUG

int main()
{

#ifdef DEBUG

    printf("Debug information enabled.\n");

#else

    printf("Debug information disabled.\n");

#endif

    return 0;
}

Output

Debug information enabled.

20.32 #if, #ifdef and #ifndef Comparison

Directive Meaning
#if Tests a preprocessing expression.
#ifdef Tests whether a macro is defined.
#ifndef Tests whether a macro is not defined.

20.33 Predefined Macros

C implementations provide several predefined macros.

Macro Meaning
__FILE__ Name of the current source file.
__LINE__ Current source line number.
__DATE__ Date the source was compiled.
__TIME__ Time the source was compiled.
__STDC__ Indicates whether the implementation conforms to a specified ISO C standard environment.

20.34 Program Using Predefined Macros

#include <stdio.h>

int main()
{
    printf("File: %s\n", __FILE__);
    printf("Line: %d\n", __LINE__);
    printf("Date: %s\n", __DATE__);
    printf("Time: %s\n", __TIME__);

    return 0;
}

The exact date, time, file name and line number depend on the compilation environment and source file.

Preprocessor conditions are evaluated during preprocessing, before ordinary C runtime execution.

20.42 Macro vs Function

Feature Macro Function
Processed by Preprocessor Compiler/runtime mechanisms
Type checking No normal function parameter type checking Yes, according to declarations
Argument evaluation May occur more than once Normally once per argument
Debugging Can be less straightforward Usually easier
Use Textual/source transformation Executable program logic

20.43 Macro vs const

Feature #define const
Handled by Preprocessor Compiler
Type No type associated with the macro itself Has a declared type
Scope behavior Controlled by preprocessing regions Follows C scope rules
Debugging Can be less convenient Generally easier
Use the mechanism that best matches the requirement. Macros are especially useful for conditional compilation and source-level substitutions; const objects are often preferable for typed constants.

20.44 Nested Conditional Compilation

Conditional directives can be nested when a program requires multiple levels of preprocessing decisions. 

#ifdef SYSTEM

    #ifdef DEBUG

        printf("System debug mode");

    #endif

#endif

20.45 Logical Operators in #if

Preprocessor expressions can use operators such as logical AND, logical OR and logical NOT. 

#define VERSION 2
#define DEBUG 1

#if VERSION == 2 && DEBUG

printf("Debug version 2");

#endif

20.46 Using defined Operator

The defined operator can be used in conditional preprocessing expressions. 

#ifdef DEBUG

printf("Debug");

#endif

An equivalent style can use: 

#if defined(DEBUG)

printf("Debug");

#endif

20.47 Conditional Compilation for Platforms

Conditional compilation can be used when different source code is required for different target environments. 

#ifdef WINDOWS

printf("Windows code");

#elif defined(LINUX)

printf("Linux code");

#else

printf("Other platform");

#endif

The actual platform macros depend on the compiler and build environment. Portable code should not assume that every implementation defines the same platform macro.

20.51 Advantages of Preprocessor Directives

  • Header files can be included conveniently.
  • Repeated source substitutions can be simplified using macros.
  • Conditional compilation supports different build configurations.
  • Header guards help prevent repeated inclusion of a header's declarations.
  • Debugging features can be enabled or disabled at build time.
  • Platform-specific source sections can be selected.
  • Common constants and configuration values can be named.

20.52 Disadvantages of Preprocessor Directives

  • Excessive macro use can make code difficult to understand.
  • Macros do not provide normal type checking.
  • Function-like macros can evaluate arguments more than once.
  • Complex conditional compilation can make code harder to maintain.
  • Preprocessor errors can sometimes be difficult to trace.
  • Macro names can conflict with identifiers.

20.53 Common Errors

❌ Error 1: Missing #

include <stdio.h>

Correct: 

#include <stdio.h>

❌ Error 2: Incorrect Macro Parentheses

#define SQUARE(x) x * x

Safer: 

#define SQUARE(x) ((x) * (x))

❌ Error 3: Missing #endif

#ifdef DEBUG

printf("Debug");

Correct: 

#ifdef DEBUG

printf("Debug");

#endif

❌ Error 4: Macro Side Effects

#define SQUARE(x) ((x) * (x))

SQUARE(i++)

Avoid passing expressions with side effects to macros that may evaluate their parameters more than once.

❌ Error 5: Macro Name Collision

#define SIZE 100

int SIZE = 20;

A macro can interfere with identifiers if names are not chosen carefully.

20.54 Best Practices

  1. Use meaningful macro names.
  2. Use uppercase names for many project-wide macros when appropriate.
  3. Parenthesize macro parameters and complete expressions.
  4. Avoid macros with arguments that have side effects.
  5. Keep conditional compilation simple.
  6. Use header guards in reusable headers.
  7. Avoid defining macros with names likely to conflict with library or project identifiers.
  8. Prefer typed C language features when they provide a clearer and safer solution.

20.63 Summary

The C preprocessor is an important part of the C translation process. It processes preprocessing directives before the resulting source code is compiled.

The most commonly used directives include #include, #define, #undef, #if, #ifdef, #ifndef, #else, #elif and #endif.

Macros can be object-like or function-like. Conditional compilation allows programmers to select source code based on preprocessing conditions.

Header guards are commonly used to prevent repeated processing of a header's contents within the same translation unit.

Easy Formula to Remember:

#include → Include
#define → Define
#undef → Remove
#if → Check condition
#ifdef → If defined
#ifndef → If not defined
#else → Otherwise
#elif → Another condition
#endif → End condition
