Chapter 17: Preprocessor Directives in C

Learn how the C preprocessor prepares source code before compilation using directives such as #include, #define, conditional compilation directives and macros.

17.1 Introduction to the C Preprocessor

The C preprocessor is a program that processes the source code before the actual compilation takes place.

It handles special instructions called preprocessor directives.

Preprocessor directives normally begin with the # symbol. 

#include <stdio.h>

#define PI 3.14159
Simple Definition:

The C preprocessor processes special instructions in the source program before the compiler translates the program into machine code.

17.2 What is a Preprocessor Directive?

A preprocessor directive is an instruction given to the preprocessor before compilation.

These directives are used for including header files, defining macros, creating symbolic constants and controlling which parts of source code are compiled.

Example

#include <stdio.h>

#define MAX 100

Here, #include and #define are preprocessor directives.

17.3 Why is the Preprocessor Needed?

  • To include required header files.
  • To define symbolic constants.
  • To create macros.
  • To conditionally compile sections of code.
  • To improve code organization.
  • To make source code easier to maintain.
  • To support platform-dependent code.

C SOURCE PROGRAM | v +-------------------+ | PREPROCESSOR | +-------------------+ | v Preprocessed Source | v +-------------------+ | COMPILER | +-------------------+ | v Object / Assembly Code | v +-------------------+ | LINKER | +-------------------+ | v Executable File

The preprocessor is therefore an early stage of the C program translation process.

17.5 Common Preprocessor Directives

Directive Purpose
#include Includes header or source content.
#define Defines a macro or symbolic constant.
#undef Undefines a macro.
#if Conditionally includes code.
#ifdef Checks whether a macro is defined.
#ifndef Checks whether a macro is not defined.
#else Provides an alternative conditional section.
#elif Provides another conditional test.
#endif Ends a conditional preprocessing section.

17.6 #include Directive

The #include directive is used to include the contents of another file into the source program during preprocessing.

Example

#include <stdio.h>

int main()
{
    printf("Hello C");

    return 0;
}

The stdio.h header provides declarations for standard input and output functions such as printf() and scanf().

17.7 Angle Brackets and Double Quotes in #include

Form Common Usage
#include <file.h> System or implementation-provided headers.
#include "file.h" Project or user-created headers.

Example

#include <stdio.h>
#include "myheader.h"

17.8 #define Directive

The #define directive is used to define a macro.

A simple macro can represent a constant value.

Syntax

#define NAME value

Example

#define PI 3.14159
#define MAX 100

int main()
{
    printf("%d", MAX);

    return 0;
}

Output

100

17.9 Symbolic Constants

A symbolic constant is a name used to represent a value. 

#define DAYS 7
#define PASS_MARK 40
#define COLLEGE "ALLIED"

Symbolic constants can make programs easier to read and maintain.

Instead of repeatedly writing a value throughout a program, give the value a meaningful name.

17.10 Program Using #define

#include <stdio.h>

#define PI 3.14159

int main()
{
    float radius = 5;
    float area;

    area = PI * radius * radius;

    printf("Area = %.2f", area);

    return 0;
}

Output

Area = 78.54

17.11 Preprocessor vs Compiler

Preprocessor Compiler
Processes directives. Translates C source code.
Handles #include and #define. Checks syntax and semantics.
Works before compilation. Works after preprocessing.
Performs macro expansion. Generates translated code.

17.12 Important Characteristics

  • Preprocessor directives begin with #.
  • They are processed before compilation.
  • Most directives do not end with a semicolon.
  • Macros are expanded during preprocessing.
  • Conditional directives can control which source code reaches the compiler.

17.13 Macros

A macro is a name defined using the #define directive.

During preprocessing, occurrences of the macro are replaced according to its definition.

Example

#define MAX 100

int x = MAX;

The macro MAX represents the value 100.

17.14 Object-Like Macros

A macro without parameters is commonly called an object-like macro. 

#define PI 3.14159
#define MAX_SIZE 100
#define NAME "ALLIED"

These macros can represent constants or other replacement text.

17.15 Function-Like Macros

A function-like macro accepts parameters and can resemble a function call.

Syntax

#define NAME(parameter) replacement

Example

#define SQUARE(x) ((x) * (x))

int main()
{
    printf("%d", SQUARE(5));

    return 0;
}

Output

25

17.16 Parameterized Macro

A parameterized macro receives one or more arguments. 

#define ADD(a, b) ((a) + (b))

int result = ADD(10, 20);

The result is: 

30
Always use parentheses carefully in macros to avoid unexpected results caused by operator precedence.

17.17 Macro Example – Maximum of Two Numbers

#include <stdio.h>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main()
{
    int x = 20;
    int y = 35;

    printf("Maximum = %d", MAX(x, y));

    return 0;
}

Output

Maximum = 35

17.18 Macro vs Function

Macro Function
Processed by preprocessor. Handled by compiler.
Uses textual replacement. Uses normal function semantics.
Does not perform normal function type checking. Provides type checking for parameters.
Can avoid function-call overhead in suitable cases. Has normal function-call semantics.
Requires careful parentheses. Generally safer for complex operations.

17.19 #undef Directive

The #undef directive removes the definition of a macro.

Example

#define VALUE 100

#undef VALUE

#define VALUE 200

int main()
{
    printf("%d", VALUE);

    return 0;
}

Output

200

17.20 Conditional Compilation

Conditional compilation allows selected sections of source code to be included or excluded depending on preprocessing conditions.

Common directives used for conditional compilation are:

  • #if
  • #ifdef
  • #ifndef
  • #else
  • #elif
  • #endif

17.21 #if Directive

The #if directive includes a section of source code when its preprocessing expression evaluates to a nonzero value.

Example

#define VERSION 2

#if VERSION == 2

printf("Version 2");

#endif

17.22 #ifdef Directive

The #ifdef directive checks whether a specified macro has been defined.

Example

#define DEBUG

#ifdef DEBUG

printf("Debug mode enabled");

#endif

If DEBUG is defined, the code inside the conditional section is included.

17.23 #ifndef Directive

The #ifndef directive checks whether a macro has not been defined.

Example

#ifndef MAX

#define MAX 100

#endif

This technique is commonly used to prevent repeated definitions in header files.

17.24 #else Directive

The #else directive provides an alternative section when the preceding condition is false. 

#define VALUE 10

#if VALUE > 20

printf("Greater than 20");

#else

printf("20 or less");

#endif

17.25 #elif Directive

The #elif directive allows another condition to be tested if the previous condition was false. 

#define VERSION 2

#if VERSION == 1

printf("Version 1");

#elif VERSION == 2

printf("Version 2");

#else

printf("Unknown version");

#endif

17.26 #endif Directive

The #endif directive marks the end of a conditional preprocessing section. 

#ifdef DEBUG

printf("Debugging");

#endif
Every conditional preprocessing block must be properly terminated with #endif.

17.27 Conditional Compilation Flow

START | v Preprocessor reads #if | v +----------------+ | Condition? | +----------------+ / \ True False | | v v Include Exclude code code \ / \ / v v #endif | v Compiler receives selected source

17.28 #if vs #ifdef vs #ifndef

Directive Purpose
#if Tests a preprocessing expression.
#ifdef Tests whether a macro is defined.
#ifndef Tests whether a macro is not defined.

17.29 Header Guards

Header guards are used to prevent a header file from being included more than once in the same translation unit.

Example

#ifndef MYHEADER_H
#define MYHEADER_H

int add(int a, int b);

#endif

The macro is defined the first time the header is included. Later attempts to include the same header can therefore be skipped.

Header guards are especially useful when creating your own C header files.

17.30 Predefined Macros

C implementations provide several predefined macros that give information about the current source location and compilation environment.

Macro Meaning
__FILE__ Name of the current source file.
__LINE__ Current source line number.
__DATE__ Date of translation.
__TIME__ Time of translation.
__STDC__ Indicates standard C conformance when supported.

17.31 Program Using Predefined Macros

#include <stdio.h>

int main()
{
    printf("File: %s\n", __FILE__);
    printf("Line: %d\n", __LINE__);
    printf("Date: %s\n", __DATE__);
    printf("Time: %s\n", __TIME__);

    return 0;
}

The exact output for __FILE__, __LINE__, __DATE__ and __TIME__ depends on the source file and compilation environment.

17.32 Stringizing Operator #

In a function-like macro, the # operator can convert a macro argument into a string literal.

Example

#include <stdio.h>

#define SHOW(x) #x

int main()
{
    printf("%s", SHOW(Hello));

    return 0;
}

Output

Hello

17.33 Token-Pasting Operator ##

The ## operator combines two tokens during macro expansion.

Example

#include <stdio.h>

#define JOIN(a, b) a ## b

int main()
{
    int number10 = 50;

    printf("%d", JOIN(number, 10));

    return 0;
}

Output

50

17.34 Multiline Macros

A macro can contain multiple lines by using the backslash character at the end of each continued line. 

#define PRINT_NUMBERS() \
do { \
    printf("1\n"); \
    printf("2\n"); \
    printf("3\n"); \
} while (0)

Multiline macros should be written carefully because they are textual substitutions.

17.35 Macro Parentheses

Parentheses are important when defining expression macros.

Unsafe Style

#define SQUARE(x) x * x

Safer Style

#define SQUARE(x) ((x) * (x))
Without proper parentheses, operator precedence can produce unexpected results.

17.36 Macro Side Effects

Function-like macros can evaluate an argument more than once. 

#define SQUARE(x) ((x) * (x))

Using an expression such as SQUARE(i++) can cause unintended behavior because the argument occurs twice.

Avoid passing expressions with side effects such as i++ to macros that may evaluate their arguments multiple times.

17.37 Program: Debug Mode

#include <stdio.h>

#define DEBUG

int main()
{
#ifdef DEBUG

    printf("Debug mode is enabled.\n");

#endif

    printf("Program is running.");

    return 0;
}

Output

Debug mode is enabled.
Program is running.

17.38 Program: Conditional Message

#include <stdio.h>

#define MARKS 75

int main()
{
#if MARKS >= 40

    printf("Student Passed");

#else

    printf("Student Failed");

#endif

    return 0;
}

Output

Student Passed

17.39 Program: Multiple Conditions

#include <stdio.h>

#define MARKS 85

int main()
{
#if MARKS >= 90

    printf("Grade A+");

#elif MARKS >= 75

    printf("Grade A");

#elif MARKS >= 60

    printf("Grade B");

#else

    printf("Below Grade B");

#endif

    return 0;
}

Output

Grade A

17.42 Advantages of Preprocessor Directives

  • Makes code easier to maintain.
  • Supports code reuse through header files.
  • Allows symbolic constants.
  • Supports macros.
  • Enables conditional compilation.
  • Helps manage platform-dependent code.
  • Supports header guards.

17.43 Disadvantages of Preprocessor Directives

  • Macro expansion can make debugging more difficult.
  • Macros do not provide normal function type checking.
  • Poorly written macros can cause unexpected results.
  • Excessive use of macros can make code harder to read.
  • Conditional compilation can make source code more difficult to follow.
  • Macro arguments can have unexpected side effects.

17.44 Common Errors

❌ Error 1: Using a semicolon after #define

#define MAX 100;

The semicolon becomes part of the replacement text.

Better:

#define MAX 100

❌ Error 2: Incorrect Macro Parentheses

#define SQUARE(x) x * x

Use parentheses: 

#define SQUARE(x) ((x) * (x))

❌ Error 3: Missing #endif

#ifdef DEBUG

printf("Debug");

#endif

Every conditional block must be properly terminated.

❌ Error 4: Using Undefined Macros Incorrectly

Make sure a macro is defined before relying on its replacement value.

17.45 Best Practices

  1. Use meaningful macro names.
  2. Use uppercase names for symbolic constants when appropriate.
  3. Put parentheses around macro parameters and expressions.
  4. Avoid macros with arguments that have side effects.
  5. Use header guards in custom header files.
  6. Do not overuse macros when a normal C feature is clearer.
  7. Keep conditional compilation simple and readable.
  8. Use comments to explain complicated preprocessing logic.

17.46 Real-World Applications

  • Operating-system dependent programs.
  • Embedded systems.
  • Device drivers.
  • Debugging systems.

17.47 Example of Platform-Specific Code

#ifdef _WIN32

printf("Windows platform");

#elif defined(__linux__)

printf("Linux platform");

#else

printf("Other platform");

#endif

This technique allows different source code to be selected depending on the compilation environment.

17.48 Important Rules of Preprocessor Directives

  • Preprocessor directives normally begin with #.
  • A directive normally occupies a preprocessing line.
  • Directives do not normally require semicolons.
  • Macro names are replaced during preprocessing.
  • Conditional blocks must have matching #endif.
  • Macro definitions should be written carefully.

17.53 Summary

The C preprocessor is an important part of the C program translation process. It processes preprocessing directives before the compiler translates the source code.

The most commonly used directives are #include, #define, #undef, #if, #ifdef, #ifndef, #else, #elif and #endif.

Macros allow programmers to define reusable replacement text. Conditional compilation allows selected portions of source code to be included depending on preprocessing conditions.

Remember:

Preprocess → Compile → Link → Execute
